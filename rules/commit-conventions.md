## Commit Conventions

- Write commits in imperative mood ("Add feature" not "Added feature").
- Keep the subject line under 72 characters.
- Separate subject from body with a blank line.
- Use the body to explain _what_ changed and _why_, not _how_.
- Reference issues or tickets where applicable (e.g., "Fixes #42").
- Keep each commit focused on a single logical change.
- Avoid mixing whitespace/formatting changes with logic changes in the
  same commit.
- Write meaningful commit messages — someone reading the log a year
  from now should understand the change.
