## Code Style

- Write code that reads like the surrounding code — match comment density,
  naming conventions, and idioms.
- Prefer clear, descriptive variable and function names over terse ones.
- Keep functions focused: each function should do one thing well.
- Use early returns to reduce nesting and improve readability.
- Avoid magic numbers; use named constants instead.
- Write meaningful comments that explain _why_, not _what_ — the code
  already shows what it does.
- Handle errors explicitly rather than silently swallowing them.
- Prefer composition over inheritance when designing data structures.
